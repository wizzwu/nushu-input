## 数据与输入引擎

- 输入字典包含 396 个不同的标准 Unicode 女书字符。
- 汉字转女书映射覆盖这 396 个字符；Noto Sans Nushu 字体覆盖全部字符。
- 与 unicode_nushu 对照数据有 8 处读音差异，见 reports/data-validation.json。保持原项目读音及对应关系。
- 使用固定小狼毫 0.17.4 的原生 x86 引擎及本机已有小狼毫 0.17.3 的 x64 引擎，分别在隔离目录中完成真实输入测试。
- 已验证全部 396 个字符都可通过江永方言无声调拼写到达候选；共测试 213 组拼写。
- 普通话 nv/yi/ren 候选、Unicode 提交、汉字/女书切换及候选翻页通过。
- 现有输入法的个人数据未用于引擎测试，测试未更改本机正在使用的 Rime 用户配置。

## Windows 检查

- NSIS 安装器压缩流通过 7-Zip 完整性检查。
- 安装包自身携带的 Python 和纯 Python YAML 解析器可离线启动、读取及合并配置。
- 五项配置保护测试通过：保留现有方案及设置、继承已有方案列表、重复配置不产生重复项、保留个人词库、异常配置停止写入。
- 修改前的文件保存在 Rime/nushu-backups；高级 schema_list 操作无法安全合并时给出错误，不丢弃原配置。
- 仍需在干净 Windows 10/11 环境验收首次安装、UAC 取消、其他管理员代授权、多用户、完整卸载和真实应用中的候选字体显示。

## 安卓离线模拟测试

环境为 Android 16 / API 36、4KB 内存页、x86_64 模拟器，通过 ARM 翻译运行最终交付 APK 内的 ARM64 原生库。
使用只读临时模拟器实例，测试产生的修改不会写回原模拟器镜像。

- 关闭 Wi-Fi 和移动数据后，全新安装并首次启动，自动完成资源部署。
- 修复并回归验证首次启动的默认主题初始化问题。
- 输入 nv，候选栏显示女书，按空格提交 𛆁（U+1B181）。
- 点击键盘可见的“汉/女”键后再次输入 nv，提交汉字“女”（U+5973）。
- 切换江永方言方案后输入 i，提交女书候选 𛋤（U+1B2E4）。
- 测试编辑器通过 ClipboardManager 复制并回读，确认女书编码保持一致。
- 覆盖安装同签名 APK 后，用户目录中的测试标记保留。
- APK 签名验证通过；两个 ABI 的原生库与固定同文 v3.3.4 官方发行文件逐字节相同。
- Manifest 未申请 INTERNET 或全盘文件访问权限，数据位于独立应用目录。

候选栏使用内置字体；测试编辑器也显式加载字体以检查提交后的字形。
其他应用若没有女书字体，可能显示方框；这与 Unicode 文本是否正确是两件事。

尚未验证物理 ARM32/ARM64 手机、Android 8 实机、不同厂商键盘授权流程和 16KB 内存页设备。当前原生库的 ELF LOAD 对齐为 4KB，不承诺所有 16KB 设备兼容。

## macOS 与云构建

- 包中鼠须管的 PackageInfo、Payload、Scripts 和 Bom 与官方固定发行包完全一致。
- 检查原始应用 Mach-O 确认同时包含 Intel x86_64 和 ARM64；女书资源脚本中执行文件权限及所有资源校验通过。
- 安装脚本分离系统资源与登录用户配置，不以管理员身份写入管理员的 Rime 数据目录。
